# Local drafts and navigation retention

Unsent owner drafts are private local data. They do not grant service authority and are excluded from ordinary project exports. The current service exposes no owner-draft storage command, so the app uses a private per-entity journal under `Library/Application Support/Checklist/OwnerDrafts`. Directories are owner-only and each draft file is owner-readable/writable only. Each replacement is atomic, synchronized and read back before the UI says **Saved on this Mac, not sent**. A failed write retains the in-memory text and shows a persistent **Not saved** explanation with **Retry draft save**. Unreadable files remain available for recovery; readable entries still load.

The journal preserves note text with its displayed recipient, answer values with their form/target generation, task edit text with its starting revision and editor state, and separate capture drafts for each project. Closing, Escape, Back and project switching do not clear these records. Legacy preference drafts are migrated with unknown origin and require explicit reconciliation. A different store incarnation does not authorize sending old drafts: notes need an explicit destination refresh, answers adopt the current form while archiving prior choices, edit drafts reconcile the current ticket revision, and captures confirm their selected project. Typing alone never approves a new origin. A competing task edit retains the original expected revision and the user's text until explicitly reconciled. Late successful saves/sends cannot erase newer local edits made while the command was pending.

The overlay keeps entity IDs, rather than list indexes, as its navigation identity. Per-item native scroll offsets, editable focus and text selections are retained for Back and reopened items. Escape first leaves an active editor, retaining its draft; the next Escape closes the overlay. The window interaction bridge restores the opening control on dismissal and preserves the ordinary action/focus of controls clicked outside. Retention never intentionally takes focus from a clicked control outside the overlay. These native helpers support macOS 14 without publishing scroll events across the whole app.

Live rows keep their identities/positions during pointer interaction or a bounded keyboard interaction. Updated content for those same IDs remains visible, while disruptive additions/removals/moves wait for an interaction boundary or **Apply updates**. Explicit filter/project changes apply immediately. An open ticket remains anchored by ID, with **Moved to…**, **No longer matches this view**, or archived/trashed feedback. Search/status/tag preferences are remembered per project along with existing selection/view settings. The sidebar retains its visibility and bounded width; the native window frame uses AppKit autosave. Reduced-motion settings suppress overlay navigation animation. No permanent third column is created.

Disconnected state preserves local drafts and rejects new authoritative mutations, including direct attachment/note requests and pending-command retries. Reconnect installs a full scoped snapshot and its cursor before enabling writes. It does not replace journal contents. A previous ambiguous command retains its exact command ID and is reconciled explicitly; the draft journal never starts a claim, completes a ticket, sends a note or answers a request by itself.

`scripts/check-local-drafts.sh` checks real journal durability/privacy/recovery plus the actual Store's draft/offline/unknown-outcome boundary using isolated preferences and a fake transport. `scripts/check-navigation-retention.swift` exercises native per-item scroll/focus and row-order retention in an isolated offscreen window. The overlay interaction fixture covers dismissal, first/second Escape, focus return, sidebar clamping and one-time frame autosave. Installed shared-build tests still need to observe close/reopen/Back, live moves, offline recovery and narrow-window behavior before claiming the full UI acceptance passed.

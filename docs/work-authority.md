# Bounded work authority

Task claims and file/lane reservations share one transaction. File scopes use `{path,access:"read"|"write"}` relative to the enrolled root or as a contained absolute path; paths resolve symlinks, Unicode normalization and volume case rules. Two live attempts cannot reserve overlapping canonical writable paths. Lane scopes use `{lane_id,units:1}` and project policy `lane_capacities`; capacity defaults to one. Read-only references can share a path. An end signal alone, age, policy revocation and service token revocation retain reservations until deliberate release, verified recovery or the qualified native-closure path below.

`work_scope_adjust` or a checkpoint with `file_scopes`/`lane_scopes` replaces the complete reservation atomically. Every addition must fit before any old reservation changes. A failure preserves the old claim and all its reservations. A parent cannot narrow a writable descendant's paths or reduce the aggregate lane units delegated to current children.

`work_delegate` offers bounded scopes to an existing registered native worker session. It does not create or launch a model. The selected session accepts with `work_child_accept`; its token belongs to its actual installation/session generation and execution domain. The service records `parent_attempt_id` and contributor provenance. Child scopes fit the parent's current envelope, sibling writes are disjoint, delegated lane units share the parent envelope, and the active tree is bounded to 32 descendants. The parent remains the ticket handler. Child release does not clear or replace the root ticket attempt.

Before parent submit, release, handoff or recovery, every active writable descendant must release or have explicit stop/file-state recovery evidence. The service refuses `CHILD_WRITERS_ACTIVE` while any remain. A read-only child may retain context after its parent releases, but the complete live ancestor chain is required before gaining or transferring write authority; an ended parent's saved scope cannot grant it again.

A healthy handoff is offer/accept. `work_handoff_offer` retains the old claim and stores a summary and exact target session generation. `work_handoff_accept` rechecks both source and recipient authority/policy, fences the old token and grants a new attempt with preserved context/scopes. A child handoff keeps its parent relationship and never replaces the root ticket handler. Offers expire semantically when their source authority or recipient binding changes; no timer releases work.

`work_takeover` replaces a live holder without its permission (owner decision, 19 October 2026). The caller needs a reason and the same eligibility as a claim in that phase; review keeps contributor independence, and an owner-assigned ticket stays with the owner. In one transaction the earlier attempt and its active delegated children become `taken_over` (tokens removed), the new attempt copies the phase, review target and scopes (or takes new scopes), records `takeover_from_attempt_id`, `takeover_reason` and the earlier progress, and every earlier holder that can receive messages gets a note naming the new holder and the reason. The earlier implementation attempts stay in the contributor history. A service-run source execution must finish first. A takeover cannot stop an external process that still edits the checkout; the note tells the holder to stop.

Owner recovery records `action:"confirm_stopped_revoke"`, a reason, `observation_refs` for verified process stop and `file_state_refs` for inspected file state. An optional attempt ID selects a descendant of the ticket for recovery before the root. Token invalidation follows these explicit observations; timeout/session end alone is insufficient. Restores and changed native authorization generations cannot resurrect authority. Lost-response command replay rotates only a still-live matching claim; semantic outcomes remain inspectable after authority ends.

Implementation contributors, including accepted child sessions and earlier implementation/handoff attempts on the task, are captured in review manifests. Review independence excludes recorded contributor principals, installations and native sessions. A genuinely separate non-contributor reviewer subagent can review on the same verified host/provider. Reused display names or changed contributor roles/model parameters do not clear contribution history; never fabricate an exported thread identity to obtain reviewer authority. Host execution domains remain connection authentication boundaries, not a blanket rejection of every worker in the host. Native child identity/communication qualification remains separate from these service authority tests.

## Confirmed native conversation closure

The owner requires a conversation whose actual process **and** applicable host registry are gone to become ended and relinquish work for pickup with history. This is a lifecycle contract, not permission to infer abandonment from ordinary inactivity. The observer must bind the real provider/session, verified process PID plus kernel start identity, current enrollment generation and host registry identity. A missing/reused PID must not be mistaken for the same process. A missing registry entry or a verified replacement must not be confused with an unreadable, malformed or permission-denied registry. Those uncertain observations fail closed.

The service owns the transition. End/fence the exact old session generation and preserve its task/attempt/message/delivery history. Claims return to eligible pickup only after existing source-execution and writable-descendant stop fences are satisfied. Closure cannot make work Done, approve a manifest, accept a review or acknowledge a message. A queued old delivery remains bound to its old session and authorization generation; another conversation at the same PID or socket path receives none of that authority or backlog.

A host can resume a closed conversation in a new process with the same native session ID (Claude Code does this). When that conversation connects again, the service verifies the new process, its registry entry and workspace like a first connection. It then gives the same session a new credential and authorization generation (`native_session_resumed`). Only a closure whose work has returned for pickup qualifies (`NATIVE_CLOSURE_PENDING` otherwise). The released claims, old attempt tokens and deliveries queued for the ended generation stay with that generation; the resumed conversation picks tickets up again with ordinary claims. It stays the same identity for review independence. An owner disconnect stays final, also after its process closes (`owner_revoked`). While the earlier process has no verified closure, a second process for the same thread is refused (`NATIVE_SESSION_MISMATCH`).

The native adapter must state its evidence capability honestly. Current Codex bootstrap verifies a signed host PID/start identity and observes the host-exported thread UUID; the shared host is not a proven per-thread process/registry boundary. Current Claude bootstrap independently checks its native PID/session/workspace registry and socket where used. Loss of a Checklist CLI/MCP shim, an XPC connection, a turn, a subscription or a persisted log is not sufficient closure evidence. A provider's loaded-thread `closed` event is not an OS process-death witness merely because its name contains “closed.” Missing lifecycle access stays unqualified until a supported observer supplies the required proof; it is not a waiver of the owner's acceptance requirement.

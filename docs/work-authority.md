# Bounded work authority

Task claims and file/lane reservations share one transaction. File scopes use `{path,access:"read"|"write"}` relative to the enrolled root or as a contained absolute path; paths resolve symlinks, Unicode normalization and volume case rules. Two live attempts cannot reserve overlapping canonical writable paths except the original same-holder members of one frozen Implementation batch under the limits below. Lane scopes use `{lane_id,units:1}` and project policy `lane_capacities`; capacity defaults to one. Read-only references can share a path. An end signal alone, age, policy revocation and service token revocation retain reservations until deliberate release, verified recovery or the qualified native-closure path below.

`work_scope_adjust` or a checkpoint with `file_scopes`/`lane_scopes` replaces the complete reservation atomically. Every addition must fit before any old reservation changes. A failure preserves the old claim and all its reservations. A parent cannot narrow a writable descendant's paths or reduce the aggregate lane units delegated to current children.

`work_delegate` offers bounded scopes to an existing registered native worker session. It does not create or launch a model. The selected session accepts with `work_child_accept`; its token belongs to its actual installation/session generation and execution domain. The service records `parent_attempt_id` and contributor provenance. Child scopes fit the parent's current envelope, sibling writes are disjoint, delegated lane units share the parent envelope, and the active tree is bounded to 32 descendants. The parent remains the ticket handler. Child release does not clear or replace the root ticket attempt.

Before parent submit, release, handoff or recovery, every active writable descendant must release or have explicit stop/file-state recovery evidence. The service refuses `CHILD_WRITERS_ACTIVE` while any remain. A read-only child may retain context after its parent releases, but the complete live ancestor chain is required before gaining or transferring write authority; an ended parent's saved scope cannot grant it again.

A healthy handoff is offer/accept. `work_handoff_offer` retains the old claim and stores a summary and exact target session generation. `work_handoff_accept` rechecks both source and recipient authority/policy, fences the old token and grants a new attempt with preserved context/scopes. A child handoff keeps its parent relationship and never replaces the root ticket handler. Offers expire semantically when their source authority or recipient binding changes; no timer releases work.

`work_takeover` replaces a live holder without its permission (owner decision, 19 October 2026). The caller needs a reason and the same eligibility as a claim in that phase; review keeps contributor independence, and an owner-assigned ticket stays with the owner. In one transaction the earlier attempt and its active delegated children become `taken_over` (tokens removed), the new attempt copies the phase, review target and scopes (or takes new scopes), records `takeover_from_attempt_id`, `takeover_reason` and the earlier progress, and every earlier holder that can receive messages gets a note naming the new holder and the reason. The earlier implementation attempts stay in the contributor history. A service-run source execution must finish first. A takeover cannot stop an external process that still edits the checkout; the note tells the holder to stop.

Owner recovery, or enrolled-worker recovery while `agent_rule_changes=allowed`, records `action:"confirm_stopped_revoke"`, a reason, `observation_refs` for verified process stop and `file_state_refs` for inspected file state. An optional attempt ID selects a descendant of the ticket for recovery before the root. Token invalidation follows these explicit observations; timeout/session end alone is insufficient. Restores and changed native authorization generations cannot resurrect authority. Lost-response command replay rotates only a still-live matching claim; semantic outcomes remain inspectable after authority ends.

Implementation contributors, including accepted child sessions and earlier implementation/handoff attempts on the task, are captured in review manifests. Review independence excludes recorded contributor principals, installations and native sessions. A genuinely separate non-contributor reviewer subagent can review on the same verified host/provider. Reused display names or changed contributor roles/model parameters do not clear contribution history; never fabricate an exported thread identity to obtain reviewer authority. Host execution domains remain connection authentication boundaries, not a blanket rejection of every worker in the host. Native child identity/communication qualification remains separate from these service authority tests.

## Review returns to implementation (CL-216)

`evidence_missing`, `not_run` and `blocked` with `blocked_on:"implementation"` (required `reason`) finish the review claim and close its request as `returned`, with the exact verdict retained. Other open requests on that target become superseded. The ticket clears its current manifest/release hold and departs every Triage, including batch Review membership. The service uses the manifest's submitted implementation attempt to identify its exact native holder; it never guesses from a planned assignee or display name. Current session generation, installation/domain/workspace, policy, readiness, prerequisites and ordinary file/lane reservations must still permit a fresh claim. A missing, ended, reauthorized or ineligible holder, or conflicting reservations, leaves the ticket Queued with a recorded code/reason for eligible pickup. Owner-only/legacy submissions without a native holder also queue; this path never mints a human action.

An eligible return creates a fresh Active implementation attempt with the earlier scopes, no inherited batch sharing or delegated authority, and `returned_from_review_id` / `review_return_from_attempt_id`. The submitted attempt and its token stay ended. No token is sent to the reviewer: only that exact holder can call `work_claim` at the current revision without scopes to pick up/rotate the fresh token. Use `work_scope_adjust` for later reservation changes. The return event, verdict's `implementation_return` and scoped note retain missing items, findings and routing. Queued delivery is not acknowledgment or native wake. `work_submit` captures a fresh manifest and requests; earlier passes do not transfer. The CL-41 unchanged-target supplemental-evidence path remains for retained legacy `evidence_requested` records only. `blocked_on:"reviewer"` (also the omitted-field default) retains Review and queues the same request for any eligible reviewer; its batch verdict retains membership. `not_run` remains distinct from a failed check.

## Confirmed native conversation closure

The owner requires a conversation whose actual process **and** applicable host registry are gone to become ended and relinquish work for pickup with history. This is a lifecycle contract, not permission to infer abandonment from ordinary inactivity. The observer must bind the real provider/session, verified process PID plus kernel start identity, current enrollment generation and host registry identity. A missing/reused PID must not be mistaken for the same process. A missing registry entry or a verified replacement must not be confused with an unreadable, malformed or permission-denied registry. Those uncertain observations fail closed.

The service owns the transition. End/fence the exact old session generation and preserve its task/attempt/message/delivery history. Claims return to eligible pickup only after existing source-execution and writable-descendant stop fences are satisfied. Closure cannot make work Done, approve a manifest, accept a review or acknowledge a message. A queued old delivery remains bound to its old session and authorization generation; another conversation at the same PID or socket path receives none of that authority or backlog.

A host can resume a closed conversation in a new process with the same native session ID (Claude Code does this). When that conversation connects again, the service verifies the new process, its registry entry and workspace like a first connection. It then gives the same session a new credential and authorization generation (`native_session_resumed`). Only a closure whose work has returned for pickup qualifies (`NATIVE_CLOSURE_PENDING` otherwise). The released claims, old attempt tokens and deliveries queued for the ended generation stay with that generation; the resumed conversation picks tickets up again with ordinary claims. It stays the same identity for review independence. An owner disconnect stays refused, also after its process closes (`owner_revoked`), until the owner selects Allow again in the ticket’s session view. Disconnect returns eligible claims to Queued with owner history; source checks and writable descendants keep reservations until explicit stopped-work recovery. Allow again is refused while those claims remain; after recovery it permits only a verified native bootstrap with a fresh credential and authorization generation, never old claims or deliveries. While the earlier process has no verified closure, a second process for the same thread is refused (`NATIVE_SESSION_MISMATCH`).

A resumed conversation may explicitly finish its earlier active Triage orchestration with a reason when its retained released closure matches that orchestration’s original session/principal, provider, execution domain and authorization generation. The finish retains the closure link and the current finishing identity; a later start links the new orchestration record. This narrow recovery does not restore checkpoint, claim or delivery authority. A different eligible coordinator uses the separate reasoned `triage_orchestrate action=takeover` route, which ends and links orchestration records and notifies the earlier coordinator without changing member claims, fixed batches or memberships. The owner’s reasoned finish stays available.

The native adapter must state its evidence capability honestly. Current Codex bootstrap verifies a signed host PID/start identity and observes the host-exported thread UUID; the shared host is not a proven per-thread process/registry boundary. Current Claude bootstrap independently checks its native PID/session/workspace registry and socket where used. Loss of a Checklist CLI/MCP shim, an XPC connection, a turn, a subscription or a persisted log is not sufficient closure evidence. A provider's loaded-thread `closed` event is not an OS process-death witness merely because its name contains “closed.” Missing lifecycle access stays unqualified until a supported observer supplies the required proof; it is not a waiver of the owner's acceptance requirement.

The [native closure route table and installed qualification procedure](integrations.md#native-conversation-closure-qualification-cl-38--cl-83) separate available observations from the real closure/address-reuse evidence still required.

## Frozen implementation cohort limits

Only one frozen **Implementation** batch may share its members' canonical writable paths, and only between its original selected top-level attempts held by the exact same authenticated principal, session, authorization generation, execution domain and store incarnation. Preparation normalizes/freezes all scopes before its rollback-only claim rehearsal; dispatch installs the internal cohort before reservation validation. There is no public overlap flag. Each ticket keeps its complete scopes, distinct attempt, token, contributor history and evidence target. Same-path, ancestor/descendant, symlink and volume-case aliases use the ordinary canonical comparison.

All other live attempts see the cohort's canonical write union. A different session/generation or frozen batch (even held by the same session) still conflicts. Partial release or individual submission keeps every remaining active member's reservation; only the last owner frees the shared path. Review reservations, lane capacity, readiness, prerequisites, policy, owner assignment and review independence remain unchanged. Scope adjustment can retain/narrow frozen shared writes but cannot expand sharing beyond the frozen member envelope. Child acceptance, handoff and takeover never inherit the original attempt's sharing permission: overlapping transfers refuse atomically until narrowed or other writers release. Reconnection cannot revive an old generation's exemption. Orchestration ownership grants no member reservation authority. Scoped conflicts identify the canonical candidate/reserved paths and both ticket IDs/keys, with batch ID/digest when present; foreign-project ticket metadata stays private.

## Advisory health supervision

[Work health](work-health.md) stores inactivity requests, no-response notes and correlated late-reply outcomes alongside existing claims. Its timer changes none of the authority rules above. A current response must revalidate the exact session/attempt/phase, material basis, ancestry and policy; changed authority requires ordinary reconciliation, preserving the newer holder. Pickup delivery is not acknowledgment, useful progress or a resumed native turn. The service never starts a model or treats health silence as qualified native closure.
